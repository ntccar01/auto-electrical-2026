# 雲端教師端部署

本版採「學生匯出提交檔 → 教師登入後匯入 → 覆閱／核章／發證」。不使用公開匿名寫入端點，不把教師權限交給學生端判定。

## 已備妥與未驗證的界線

- Code.gs：教師白名單、提交檔匯入／去重、調分、核章、學期證書快照與 HMAC 簽章。另提供只回傳遮罩資料的學生證書查驗函式。
- Teacher.html：教師管理頁；核發後可複製學生查驗連結。
- StudentVerify.html：學生查驗與列印頁，只顯示遮罩班級／座號、學期、單元與核發日，不顯示姓名、分數或教師帳號。
- appsscript.json：V8、臺北時區與必要的 Sheets／帳號 email 權限。
- 2026-11-03 已由教師帳號實測既有雲端流程：匯入、教師核章、核發與簽章查驗成功；測試假資料已由使用者清除。
- 新增的學生查驗程式目前只在本機，尚未更新 GAS 程式或建立學生部署。瀏覽器／mock 測試不代表新查驗頁已獲 Google 線上驗證。

## 第一次部署（教師本人）

1. 用教師的 Google 帳號建立專用試算表，保留私人存取，記下試算表網址中的 ID。
2. 從試算表的「擴充功能 → Apps Script」建立綁定專案。
3. 將本目錄 Code.gs 貼入指令碼，建立名為 Teacher 的 HTML 檔並貼入 Teacher.html，再建立名為 StudentVerify 的 HTML 檔並貼入 StudentVerify.html。
4. 在專案設定顯示 appsscript.json，貼入本目錄的 manifest。
5. 在「專案設定 → 指令碼屬性」加入：
   - SPREADSHEET_ID：步驟 1 的試算表 ID。
   - TEACHER_EMAILS：教師帳號 email；多個帳號用逗號分隔。此值只放伺服器，不放學生端。
6. 部署為「網頁應用程式」，執行身分選教師本人，存取權限選「僅限自己」。第一次由教師本人完成 Google 授權。
7. 開啟部署網址，確認管理頁能讀取空成績列表。若身分 email 取不到，後端會拒絕，不會退回匿名存取。
8. 將部署網址寫到 shared/js/config.js 的 gasUrl（https://script.google.com/macros/s/.../exec），設定 semester，例如 115-1。網址是教師管理入口，不是學生 POST API。

目前「僅限自己」部署只服務部署教師本人；白名單不會繞過 Google 部署權限。多教師協作需另行確認學校 Workspace 的存取政策與授權方式。

## 學生領證及查驗（分開部署）

教師部署與學生查驗部署必須是兩個不同的網頁應用程式部署 URL：

1. 更新原有教師部署至新版本，維持「以部署者執行」及「僅限自己」；不要把教師管理入口改成公開。
2. 在同一 Apps Script 專案建立第二個網頁應用程式部署。執行身分選部署教師本人。存取範圍優先選能涵蓋學生帳號的網域或 Google 帳號登入範圍；先不要選匿名存取。若學校管理政策不允許，先停下來詢問管理員，不要為了測試放寬教師部署。
3. 複製第二個部署的 `/exec` 網址，到「專案設定 → 指令碼屬性」新增 `STUDENT_VERIFY_URL`。此值是學生查驗部署網址，不含 `?page=verify` 或證書 ID。
4. 回到教師部署核發證書，教師端會產生「學生查驗連結」；複製後交給學生。學生使用連結可查驗並列印／另存 PDF。
5. 用學生帳號測試有效 ID、錯誤 ID、列印頁；確認教師管理部署仍要求教師帳號，公開頁只回傳有效狀態與遮罩資料。

公開查驗網址只會路由到 StudentVerify 頁；匯入、讀取成績、調分、核章、發證及教師查驗仍須通過 `teacher_()` 白名單。公開查驗函式只回傳 `valid`、證書 ID、遮罩班級／座號、學期、單元與核發日。簽章金鑰和完整證書快照不回傳給瀏覽器。學生查驗目前使用證書 ID；持有連結者可查到上述遮罩資料，因此只分享給證書本人或必要對象。

`STUDENT_VERIFY_URL` 尚未設定前，教師仍可核發證書，但分享連結欄會保持空白。GAS 專案存取選項會受 Google Workspace 管理政策限制；本機測試不能代替學生帳號的線上權限驗證。

## 使用方式

1. 學生完成考評後，下載「匯出提交檔」的 JSON；CSV 仍可保存人類可讀成績。
2. 教師收集提交檔，也可在本機 teacher.html 依單元／班級篩選後按「匯出雲端提交檔」。檔案只含班級代號、座號、題目、紀錄 ID 與前端初評。
3. 教師登入雲端管理頁，輸入本批匯入學期並選檔匯入。每批 1～200 筆，檔案上限 1 MB。未指定批次學期時，檔案內各筆必須已有學期。
4. 伺服器以 recordId 去重；本機調分、核章、姓名與額外欄位不會被當成雲端授權資料。
5. 教師覆閱後調分或核章，核章身分取自 Google 帳號，核章後鎖定。
6. 依班級代號、座號、學期核發證書。雲端 ID 不含學生識別碼，證書保存已核章紀錄的快照。
7. 教師端可查驗雲端證書；學生請使用 StudentVerify 獨立部署的查驗連結。專案根目錄 verify.html 仍只查本機，不能替代雲端查驗。

NTC_Grades 與 NTC_Certificates 工作表由首次使用時建立。請不要手動修改內部 ID 或 JSON 欄位。CERT_SIGNING_KEY 在首次雲端核發時自動產生並留在指令碼屬性；更換或刪除會使舊證書無法通過簽章查驗。

匯入的初評仍來自學生瀏覽器，不能視為防作弊證據；教師須核對操作歷程或課堂表現後再核章。學生查驗頁只驗證證書 ID，不提供成績提交或帳號登入；即時學生登入提交仍需另外設計身分驗證。不要把教師管理部署改成公開。

## 面試報告第一版（2026-11-03）
學生查驗雲端第 5 版已由使用者實測，測試資料已清理。本機同步移除 StudentVerify 的錯誤範本標記檢查。新增 InterviewReport.html 與教師報告產生操作：教師確認學生同意後，只取指定班級／座號／學期已核章紀錄，簽署初評、調整後成績與評量分項快照，保存於 NTC_InterviewReports，30 天後停止線上查驗。未保存姓名，也不公開教師帳號、調分私註或原始提交資料。
報告連結使用 STUDENT_VERIFY_URL 加上 page=interview；持有連結的 Google 登入者可看到未遮罩班級、座號及成績，應由學生主動提供面試者。身份仍須比對學生證及校方資料。刪除對應報告列可撤銷；已匯出的 PDF 無法撤回，須線上確認效期。新功能僅本機實作，尚未部署或 Google 線上驗證，未提交。

## 學生代碼與成績檔（CSV）匯入（2026-11-11，第 1 階段）

學生不需登入 Google。考評結果畫面按「下載成績檔（交給老師）」，輸入老師發的 6 碼代碼後下載 CSV，用通訊軟體傳給老師；老師在本管理頁檢查並匯入。

### 更新既有 Apps Script（不需新增部署）

1. 把本目錄最新的 Code.gs、Teacher.html 貼到既有 Apps Script 專案對應檔案，儲存。
2. 「部署 → 管理部署作業」→ 教師部署 → 編輯 → 版本選「新版本」→ 部署。存取權限維持「僅限自己」。
3. 第一次建立名單時會自動新增 NTC_Roster 工作表，不要手動修改其中的 pinKey 或 JSON。

### 使用方式

1. **建立名單**：在「學生名單與 6 碼代碼」輸入班級代號、起訖座號，按「產生代碼」，再按「列印代碼條」剪下發給學生。代碼只顯示這一次，試算表只存 pinKey（由班級、座號與代碼計算的雜湊），不存代碼原文。已有代碼的座號會略過。
2. **學生休學／轉出**：輸入座號按「移除此座號」，代碼立即失效，已匯入成績保留。
3. **忘記代碼**：輸入座號按「重設此座號代碼」，舊代碼立即失效，新代碼只顯示一次。
4. **收檔匯入**：在「匯入學生成績檔（CSV）」選擇多個學生傳來的原始 CSV（一次最多 100 個、每個 100 KB 內），先按「檢查檔案」：
   - ✅ 驗證通過：代碼正確、內容未被修改。
   - ⚠️ 內容被修改／可讀欄位被修改（例如用 Excel 改了總分）／格式錯誤：一律不匯入。
   - ❔ 未簽章／名單中無此座號：預設不匯入；勾選「也匯入…」才會匯入，並在成績表標示來源。
   - 練習模式紀錄、重複檔：不匯入。
5. 按「匯入檢查結果」。成績表「來源／驗證」欄顯示 CSV 驗證狀態與第幾次繳交，仍須覆閱後核章。

### 界線與限制

- 學生 CSV 用 Excel 開啟後另存，簽章可能失效，請匯入原始檔。
- 代碼能確認「是哪個座號交的、內容沒被改」，無法防止同學互借代碼；正式考評仍需課堂監考。
- 分數仍是學生端初評；考評「通過」需同時符合：診斷正確、配線完成、至少 2 筆有效量測（電壓與電阻檔都用到）、總分 60 分以上。


## 學生線上上傳（2026-11-12，第 2 階段）

老師在管理頁「開放學生線上上傳」輸入班級與分鐘數（5～240，預設 50）按「開放上傳」，該班學生即可在考評結果畫面按「☁️ 上傳成績」，輸入 6 碼代碼直接寫入成績表；時間到自動關閉，也可按「關閉上傳」。沒開放、網路失敗時，學生會被引導改下載成績檔。

### 一次性設定：建立上傳專用部署

1. 先照前述方式更新 Code.gs、Teacher.html，並以「編輯既有教師部署 → 新版本」部署（教師部署仍為「僅限自己」）。
2. 「部署 → 新增部署作業 → 網頁應用程式」：說明填「學生上傳」，**執行身分：我**，**誰可以存取：任何人**，按部署並授權。
3. 複製這個新部署的網址（…/exec），貼到 `shared/js/config.js` 的 `uploadUrl`，推送 GitHub。
4. 以後更新程式時，教師部署與上傳部署都要「編輯 → 新版本」。

### 安全設計

- 上傳端點（doPost）只接受：開放中的班級、名單內座號、以該座號代碼簽章、考評模式、未重複的紀錄；成功寫入的來源標示「線上上傳」。
- 代碼錯誤：同一班級座號連錯 5 次鎖 10 分鐘（CacheService）。
- 繳交次數由伺服器依同一班級、座號、單元、試卷、難度、日期（臺北時間）的既有紀錄計算，學生清瀏覽器或換電腦不會歸零；學生端算的次數另存 clientAttempt 供對照。
- 「任何人」部署打開網址只會看到「無教師權限」，教師管理功能仍只限白名單帳號。
- 限制：無法防止同學互借代碼；分數仍為學生端初評，須覆閱核章。
